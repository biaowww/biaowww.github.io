// 四个设计方案，点进去都能真的交互 · 2026-07-22

四个方案都围绕同一组诉求做：面板放开篇、以 7 个身份标签为主线索、点身份触发点亮、把「经历超杂」具象化。 数据完全相同（12 段人生章节 / 28 个技能 / 7 个身份），差别只在怎么组织和怎么点亮。 排名来自一轮独立评审，仅供参考——你的直觉比评分重要。
评审排名 1

A · 转职树

Job Tree — 从下往上长的真树

树干是人生时间线（2007 在根、NOW 在冠），每次转职是树干上的分叉，支线是斜出的细枝，技能是挂在枝上的叶。点身份标签，那条枝连叶亮起来、其余褪灰。

最像树开篇面板点亮机制偏弱

强 唯一一棵几何上真的树，枝干是算出来的，好看到可当装饰

弱 7 个身份的点亮方式其实是同一套，只是位置不同；手机要横滑

评审排名 2

D · 根系图

Root System — 倒过来的树

上方是「现在的我」，往下扎根：三条主根（数据/创作/商业）分出须根，末端是技能，越早的经历埋得越深。点身份，根须从末端往上流动点亮——「这段经历供养了我今天的哪些能力」。

隐喻最好深度=年代根画得偏直

强 会自动算出「创作线空了十年」这种数据自己说的话

弱 根系横向摆幅太小，看起来像梳齿不像根；手机三屏偏空

评审排名 3

B · 技能星盘

Sphere Grid — FFX / PoE 式径向星图

中心是立绘，7 个身份是环绕的枢纽，技能作为卫星沿轨道分布连成星座。点枢纽，该星座亮起。独有机制：「借来的技能」——一个技能可以同时属于多个身份，点开能看到跨界复用。

交互最聪明不是树手机字太小

强 「借来的技能」是四个方案里唯一有信息增量的交互

弱 你要的是树，它给的是星盘；窄屏下枢纽文字偏小

打开方案 B →
评审排名 4

C · 角色选择大厅

Character Select — 格斗游戏选人界面

首屏就是选人画面：大立绘 + 7 张职业卡牌。切职业时立绘换配色、称号变、属性条重新分配并动画、技能区只留该职业解锁的。树是附属展示。

第一眼最强卡牌完整树最弱

强 从那张横幅里精准裁出 7 个职业小人，零额外素材

弱 树最不像树；换装用的滤镜原本会把奶油底转成紫蓝（已调弱）

打开方案 C →

评审的建议：选 A，然后把 B 的「借来的技能」机制和 C 的卡牌/精灵裁切移植进去——三者的长处不冲突。

需要你拍板的一件事：手机上是接受横滑看树，还是为窄屏单独出一个纵向单列形态？这是产品取舍，不该由实现者默认。
